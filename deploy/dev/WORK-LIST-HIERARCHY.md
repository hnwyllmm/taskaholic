## 展示与接口

- 首页和侧栏只展示原始任务。`GET /api/v1/work/tasks?scope=roots` 先按实际父子关系排除子任务，再取最近 500 件，避免大量新评审把原任务挤出列表。原接口不带 scope 或带 scope=all 时行为不变，首页待处理箱和 PR 登记等调用不受影响。
- `DECOMPOSED_INTO` 和 `REVIEWS` 是层级关系，普通依赖不用于隐藏任务。只使用两端都具有工作台的关系，避免把任务藏在无法访问的旧式任务下面。
- `GET /api/v1/work/tasks/{id}/hierarchy` 返回直接子任务、上级与最原始任务入口。每层详情都可继续查看下级，旧子任务链接仍有效。子任务可查看自己的对话、交付物和验收记录，继续沿用原 Session。
- 根列表的进度统计覆盖下级任务并去重；“需要你”按原始任务计数，不把一件任务及多个待处理子任务重复计数。原始 Task 状态不改写，列表另显示子任务提醒。受阻、待验收和待回复筛选也可找到含相应子任务的原始任务。
- 已被新 head 替代的评审折叠为历史记录，不计入当前完成进度或待处理数量，不删除其报告。子任务状态每 5 秒刷新，即使父任务版本没变化，也不依靠重新读取整份父任务对话来更新状态。
- 沿用既有样式，以原始任务、分工列表和返回导航表达层级；切换原任务/子任务时确认未发送消息，取消切换不会丢草稿。

这次是只读查询与页面调整，schema 保持 13，不改写任务、成员、归属、Session、评审状态或调度协议。
